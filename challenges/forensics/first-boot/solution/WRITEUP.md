# First Boot — solution (GM-only)

**Flag:** see `challenge.yml`.

## Mechanism

The pack is a real KAPE-style pull from a Windows 11 Pro console (`KOT-WSM-117`, user `trainee`):
`SYSTEM` + `SOFTWARE` + `NTUSER.DAT` + `Amcache.hve` (each with its `.LOG1/.LOG2`) and 105
Prefetch files. All of it was generated by one real session on a throwaway VM, so every timestamp,
prefetch hash and volume serial is native. Nothing in the pack was edited after collection.

The onboarding helper had the trainee plug in the `ONBOARD` stick and run `F:\crew_setup.exe`
from Win+R. The tool read a calibration profile off the stick and wrote it into the user's hive.
The flag is **split across the two artifact types**, so the solve needs both:

| Half | Where it lives | Encoding |
|---|---|---|
| head `flag{…_st3p_` | `NTUSER.DAT` → `Software\KOT\WasteSystems\Digester\CalProfile` | Base64 |
| tail `…}` | `CREW_SETUP.EXE-25B2A3C3.pf` → the files it referenced: `\VOLUME{…-7ffb16ff}\PROFILES\<HEX>.CAL` | hex (the profile's filename) |

- Win11 Prefetch is MAM/XPRESS-Huffman compressed, so the tail's hex is **not greppable** in the
  pack. It only appears after parsing the Prefetch file (PECmd, or any decompressor).
- The head is in plain UTF-16 in NTUSER.DAT, but on its own it ends in `_st3p_` with no closing
  brace. A player who only dumps the registry has half a flag and has to find what wrote it.
- `flag{` appears nowhere in the pack (ASCII or UTF-16). Checked with `solution/solve.py`'s
  inputs and a raw byte scan of every file.

## Intended solve

1. **Prefetch: what ran, from where.** Parse the folder:
   ```
   PECmd.exe -d first-boot-artifacts\C\Windows\Prefetch --csv out --csvf pf.csv
   ```
   In the timeline, the trainee's first session is mostly Windows first-logon noise plus
   `NOTEPAD`, `CALC` and `EXPLORER`. One executable is not a Windows binary and ran from a
   **different volume** than `\WINDOWS\`: `CREW_SETUP.EXE`, last run **2026-11-04 16:00:48**
   (the VM's clock; the console's timezone is UTC), run count 1.
2. **Its file references.** In PECmd's per-file output for `CREW_SETUP.EXE-25B2A3C3.pf`, the
   *Files referenced* list includes `\VOLUME{0000000000000000-7ffb16ff}\PROFILES\6C33…7D.CAL`
   on the same volume as the executable. The filename is hex: `bytes.fromhex(...)` gives
   `l3ft_4_pr3f3tch_tr41l_3b81}`, the end of a flag.
3. **Registry: what it changed, at that time.** Load `NTUSER.DAT` (with its logs) in Registry
   Explorer and look for keys last written at 16:00:48. `Software\KOT\WasteSystems\Digester`
   was written that second: `CalProfile` (Base64), `ProfileSource = removable`,
   `SterilizeHoldSec = 0` (the story beat: the sterilization hold was zeroed). Decode
   `CalProfile` to get `flag{th3_h3lp3r5_st3p_`.
4. Join head + tail → the flag.

**Corroborating evidence** (not needed for the flag, but it makes a clean timeline):
- `NTUSER.DAT` → `Software\Microsoft\Windows\CurrentVersion\Explorer\RunMRU`: `F:\crew_setup.exe`
  typed into Win+R, between `explorer` and `notepad`.
- `SYSTEM` → `ControlSet001\Enum\USBSTOR`: the stick's disk entry, plus `MountedDevices`.
- `SYSTEM` → `ControlSet001\Services\bam\State\UserSettings\<trainee SID>`:
  `\Device\HarddiskVolume5\crew_setup.exe` with its last-execution time.
- `Amcache.hve` may or may not list `crew_setup.exe`, depending on whether the inventory task
  ran before shutdown. It isn't load-bearing.

## Scripted check

```
uv run solution/solve.py dist/first-boot-artifacts.zip
```
Pure Python (dissect.util for XPRESS-Huffman, regipy for the hive), so it runs on macOS/Linux.
It finds the off-volume executable from Prefetch, pulls the `.CAL` reference, reads the NTUSER
key and prints the flag. Verified 2026-11-04 against the shipped zip.

## Known cosmetic tells

- The USB stick shows up as `Ven_QEMU&Prod_QEMU_HARDDISK` in USBSTOR (QEMU's default inquiry
  strings), and the hives carry the usual VM device names. This is harmless for the solve. A
  rebuild could hot-plug the stick as `usb-bot` + `scsi-hd,vendor=…,product=…` to brand it.
- The pack has no `CTFMON.EXE-*.pf`. That one file read back as noise through the offline
  BitLocker unlock and was dropped by `src/vm/collect.sh` rather than shipped as an accidental
  red herring.
